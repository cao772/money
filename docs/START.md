# Codex 接手与验收

## 第一次运行
- 先读取 AGENTS.md、README，记录 git rev-parse HEAD。
- 使用 Python 3.10+，运行 python -m unittest discover -s tests -v；不要预设通过。
- 用合成任务演练 init → enqueue → claim → finish/block → report。用真实测试日志作为测试证据，不把合成数据算经营收入。
- 从用户授权的私有 Notion 总控导入真实机会；保留 ID 和验收条件，核查是否已完成，避免重复。没有连接权限时明确报告。

## P0：第一轮可交付实验
不要先花几周造大平台。根据私有台账优先级选一项：
- HTML5 原创网页游戏：核查资产许可，制作或复用获授权的可玩 MVP；输出 index.html/ZIP、移动端与桌面测试、英文简介、封面与发行平台规则核查。只准备发行，不擅自公开。
- 通用 Three.js 模板：离线可运行、配置与示例、许可证清单、打包校验；核实数字商品销售及收款路径。
- 表格处理：用合成数据做确定性匹配/清洗工具，验证空值、重复、一对多、保留原值、错误报告、安装与交付；核实需求和定价。
上述为通用实验类型；实际优先级、机会证据与业务数据以私有台账为准。

## P1：打通工程闭环
使用[连接器交接流程](CONNECTOR.md)先做 dry-run，再导入行动卡、按任务 ID 领取限时租约并回读证据。只在授权私有工作区核对本人审批记录。

## P2：每日运行与经营闭环
GPT 定期查台账、研究和复核；Codex 在本机或授权环境配置定时领取，处理可逆本地任务。记录机器/依赖/日志、重试上限和失败原因。以工作区调度器的设置及每次执行回执核实运行情况。
渠道适配按实际规则逐步推进：准备 → 明确授权后提交 → 审核 → 发行 → 真实成交 → 真实结算。真实账本区分币种、金额、费用、退款、结算证据；未知不是 0。先实现一条完整链路再扩大规模。

## 私有行动卡合同
必填：task_id、opportunity_id、目标、事实来源与核验日期、验收条件、成本预算、许可/风险、执行环境、依赖、负责人。
回写：task_id、状态、UTC 时间、代码提交/产物哈希、真实命令和退出码、证据位置、阻塞、后续动作。
审批卡另含：待本人操作、官方入口、理由、费用、授权范围、批准后的动作、停止条件。人工批准只在私有工作区由本人记录，不能由模型代填。
